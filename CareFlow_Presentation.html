1. Problem and Motivation

The Ambulatory Care Coordination & Safety Crisis

⚠️ Fragmented Intake & Departmental Misdirection

Walk-in clinic attendees describe distress colloquially or with phonetic typos (*“fevor”, “loose motion”*). Clerks guess specialties, leading to misdirected consultations and multi-day care delays.

🚨 Dangerous Hallucinations in Chatbots

Unconstrained LLMs routinely recommend antipyretic NSAIDs (Ibuprofen / Aspirin) for high fever and petechiae. In thrombocytopenic Dengue, blood-thinning NSAIDs precipitate catastrophic internal hemorrhage.

⏱️ Missed Subtle Emergencies

Standard chatbots miss atypical critical presentations—such as cauda equina syndrome (*“backpain with bladder loss”*) or transient stroke (*“facial droop”*)—casually advising rest instead of immediate 911/112 ER care.

🛡️ CareFlow Architectural Solution

Decomposes clinical coordination into specialized Python agents in LangGraph with deterministic regex emergency guardrails, evidence-grounded RAG protocols, and human physician sign-off.

2. Proposed Approach • Security Innovation

Patient Identity Security & Dual-Invariant Lifecycle Subsystem

register(P, ID) schedule / retire [Unallocated] ─────────────► [Active (Assigned)] ─────────────► [Retired [Locked]] ID not in registry • Bound strictly to Owner • Non-Reusable • status = "active" • status = "used" │ │ ▼ ▼ [Same-Owner Chat: Allowed] [Any Reuse: Blocked!] [Cross-Patient Claim: Blocked!]

Invariant 1: Strict Ownership Exclusivity (ƒ1)

∀ p1, p2 ∈ 𝒫: BoundID(p1) = BoundID(p2) ⇒ p1 = p2

A Patient ID belongs exclusively to that specific individual. If another patient attempts to use or hijack an existing ID, the system immediately returns an HTTP 400 Ownership Violation, preventing cross-patient chart contamination.

Invariant 2: Single-Use Lifecycle Non-Reusability (ƒ2)

∀ ID ∈ 𝒰: State(ID) = Retired ⇒ PermitEncounter(ID) = False

Once a Patient ID is consumed for an appointment booking or completed consultation, it is permanently locked into a Retired state. Stale reuse is blocked with an HTTP 400 Single-Use Violation, requiring the generation of a fresh unique ID (PT-1002, PT-1003).

2. Proposed Approach

Architectural Justifications: Multi-Agent vs. Monolithic LLM

🛡️ Pre-Inference Determinism

Rationale: Autoregressive token sampling cannot mathematically guarantee negative medical constraints. Decoupling safety to regex automata guarantees 100% emergency recall.

⚡ Non-Blocking ASGI Concurrency

Rationale: LangGraph synchronous invocation blocks Uvicorn's async event loop. Offloading graph execution to worker threadpools via run_in_threadpool slashed latency from >3.5s to 6.24ms.

🔄 Zero-Downtime Offline Resilience

Rationale: Hospital networks and external cloud LLMs experience outages. Dual online/offline engine falls back to local clinical knowledge in <10ms with zero network calls.

🔒 Identity Cryptographic Safety

Rationale: Unconstrained chat sessions allow accidental collision and stale token reuse. Finite-state registry enforces single-use retirement and absolute patient ownership.

👨‍⚕️ Clinician-in-the-Loop Accountability

Rationale: Healthcare liability forbids fully autonomous prescriptions. AI issues provisional tokens; certified nurses/doctors review and approve printable PDF passes.

📄 Deterministic Clinical Artifacts

Rationale: Conversational text lacks permanence. Automated ReportLab compiler generates official, legally auditable PDF referral slips with security tokens.

5. Engineering Challenges & Practical Solutions

Six Core Technical Challenges & Implemented Solutions

1. Safety vs. Hallucination

Issue: LLMs hallucinate Aspirin in Dengue.

Fix: Upstream deterministic regex guardrail (safety_agent.py) running in <0.1ms.

2. ASGI Event-Loop Freezing

Issue: Sync LangGraph blocked async Uvicorn.

Fix: Offloaded graph execution via run_in_threadpool, stabilizing latency to 6.24ms.

3. ChromaDB Cold Starts

Issue: 80MB ONNX download failed offline.

Fix: Cached singleton (_CHROMA_COLLECTION) + local file probe & BM25 fallback.

4. Typo-Laden Colloquial Input

Issue: *“fevor”* broke string match; LLMs slow.

Fix: Fuzzy sequence matcher (difflib) + 150+ alias clinical dictionary in <0.5ms.

5. Race Conditions & HITL

Issue: Parallel agent writes & legal liability.

Fix: Typed Pydantic state (CareFlowState) + mandatory clinician sign-off on HITL Desk.

6. Patient ID Collisions & Reuse

Issue: Shared static IDs mixed patient charts.

Fix: Centralized registry enforcing strict ownership binding & atomic retirement upon booking.

6. Limitations and Future Work

Current Prototype Limitations & Stage-2 Roadmap

Current Limitations

  • Simulated Hospital Roster: Uses in-memory schedules rather than a live hospital Electronic Health Record (EHR) database.
  • Text-Only Intake: Currently operates via browser text chat and onboarding modal without native audio speech transcription.
  • Complex Multisystem Comorbidities: Highly complex cases with competing contraindications still require immediate direct physician evaluation.

Stage-2 Clinical Roadmap

  • HL7 / FHIR Integration: Direct bidirectional adapter syncing appointment tokens into enterprise EMRs (Epic, Cerner).
  • Multilingual Voice Intake: Whisper speech-to-text integration for real-time vernacular voice triage in Hindi, Telugu, and Tamil.
  • Hospital Ambulatory Pilot: Conducting an observational clinical trial in an outpatient facility to measure care coordinator time savings.
